### 01. tenants
TITLE: 🏛️ Table tenants — Gestion des organisations clientes (Core SaaS Multi-Tenant)
NOTE: 👉 Cette table représente les organisations clientes de la plateforme (coopératives, tontines, entreprises).
NOTE: 👉 Elle contient uniquement l’identité et les informations administratives du tenant.
  - id | BIGINT | PK, Identity | Identifiant interne
  - uuid | CHAR(36) | NOT NULL, UNIQUE | Référence externe
  - location_id | BIGINT | FK → locations.id | Siège principal
  - code | VARCHAR(100) | NOT NULL, UNIQUE | Code organisation

  - short_name | VARCHAR(100) | NULL | Nom UI
  - slug | VARCHAR(255) | NOT NULL, UNIQUE | Routing web
  - organization_type | VARCHAR(30) | ENUM | Coopérative, tontine…
  - description | TEXT | NULL | Présentation
  - slogan | VARCHAR(255) | NULL | Devise
  - logo | VARCHAR(255) | NULL | Branding
  - cover_image | VARCHAR(255) | NULL | UI branding
  - email | VARCHAR(255) | UNIQUE | Contact officiel
  - phone | VARCHAR(50) | NULL | Contact
  - whatsapp_number | VARCHAR(50) | NULL | Contact rapide
  - status | VARCHAR(20) | DEFAULT 'ACTIVE' | État du tenant
  - configuration_completed | BOOLEAN | DEFAULT FALSE | Configuration finie
  - configured_at | TIMESTAMP | NULL | Fin configuration
  - configured_by | BIGINT | FK → users.id | Responsable config
  - version | INT | DEFAULT 1 | Concurrence
  - created_at | TIMESTAMP | DEFAULT CURRENT_TIMESTAMP | Audit
  - updated_at | TIMESTAMP | DEFAULT CURRENT_TIMESTAMP | Audit
  - deleted_at | TIMESTAMP | NULL | Suppression logique
  - created_by | BIGINT | FK → users.id | Audit
  - updated_by | BIGINT | FK → users.id | Audit
  - 🔑 CONTRAINTES MÉTIER - Table tenants |  |  | 
  - Nom de la contrainte | Définition | Type | 
  - uq_tenants_uuid | UNIQUE(uuid) | Unicité | 
  - uq_tenants_code | UNIQUE(code) | Unicité métier | 
  - uq_tenants_slug | UNIQUE(slug) | Unicité URL | 
  - ck_tenants_status | CHECK(status IN ('ACTIVE','SUSPENDED','ARCHIVED','PENDING')) | Enum |

### 59. workflow_conditions
TITLE: 🧾 Table workflow_conditions — Conditions de transition des workflows
NOTE: 👉 Cette table définit les règles métier permettant de déterminer le chemin d'exécution d'un workflow.
NOTE: 👉 Elle permet de créer des workflows conditionnels en fonction des données métier (montant, type de prêt, catégorie de dépense, statut d'un membre, etc.).
NOTE: 👉 Elle est essentielle pour automatiser les décisions et orienter dynamiquement les demandes vers les étapes appropriées.
NOTE: 👉 Elle constitue le moteur de décision (Business Rules Engine) du Workflow Core.
  - id | BIGINT | PK | Identifiant unique de la condition
  - uuid | CHAR(36) | NOT NULL | Identifiant global de la condition
  - tenant_id | BIGINT | NOT NULL, FK → tenants.id | Organisation concernée
  - workflow_id | BIGINT | NOT NULL, FK → workflows.id | Workflow auquel appartient la règle
  - workflow_step_id | BIGINT | NOT NULL, FK → workflow_steps.id | Étape à partir de laquelle la condition est évaluée
  - field_name | VARCHAR(100) | NOT NULL | Champ utilisé dans la condition (amount, member_type, account_type, etc.)
  - operator | VARCHAR(20) | NOT NULL | =, !=, >, >=, <, <=, IN, NOT IN, BETWEEN, LIKE
  - comparison_value | VARCHAR(255) | NOT NULL | Valeur utilisée pour évaluer la condition
  - logical_operator | VARCHAR(10) | DEFAULT 'AND' | AND ou OR entre plusieurs conditions
  - next_step_id | BIGINT | NOT NULL, FK → workflow_steps.id | Étape vers laquelle le workflow est dirigé si la condition est satisfaite
  - priority | INT | DEFAULT 1 | Ordre d'évaluation des conditions
  - is_default | BOOLEAN | DEFAULT FALSE | Condition utilisée si aucune autre n'est satisfaite
  - is_active | BOOLEAN | DEFAULT TRUE | Condition active ou inactive
  - sync_status | VARCHAR(20) | DEFAULT 'SYNCED' | État de synchronisation système
  - version | INT | DEFAULT 1 | Gestion de concurrence
  - created_at | TIMESTAMP | DEFAULT CURRENT_TIMESTAMP | Date d'enregistrement
